CNAME zip -r site.zip index.html CNAME curl -F " [email&#160;protected] " \ -H "Authorization: Bearer sk_yourkey" \ https://api.drop.cat/deploy The CNAME file is the source of truth for the site's custom domain. Each deploy applies it as follows: Present → customDomain is set or updated to that hostname. Absent → customDomain is cleared. The CNAME file is read for its value and removed before upload — it is never served. The files count in the response reflects only what is actually served. The site's siteId and dropcat URL never change; only customDomain does. You still need to point your DNS at dropcat for the custom hostname to resolve. Errors: INVALID_DOMAIN (bad hostname), DOMAIN_BLOCKED (reserved/blocked label), DOMAIN_TAKEN (already attached to another site). A confirmation link is sent to the provided email. Once confirmed, your account upgrades to the free tier (more sites, longer expiry, key recovery). curl -X POST \ -H "Authorization: Bearer sk_yourkey" \ -H "Content-Type: application/json" \ -d '&#123;"email": " [email&#160;protected] "&#125;' \ https://api.drop.cat/account/email Response 200 { "message": "Confirmation email sent. Check your inbox." } Note: This does not upgrade the account immediately. The user must click the confirmation link in the email. The token expires after 24 hours. Confirm Email GET /account/confirm?token=... Called by the static confirmation page at /confirm after the user clicks the link in their email. Validates the token, upgrades the account to the free tier, and extends all site expiry dates. Response 200 { "message": "Email confirmed. Your account has been upgraded." } On invalid or expired tokens, returns a 400 error. Recover Account POST /account/recover Lost your API key? If you confirmed an email, request a new key. A recovery email is sent with a fresh key. The old key is invalidated immediately. curl -X POST \ -H "Content-Type: application/json" \ -d '&#123;"email": " [email&#160;protected] "&#125;' \ https://api.drop.cat/account/recover Response 200 { "message": "If this email exists, a new key has been sent." } Note: Always returns the same response regardless of whether the email exists, to prevent enumeration. Authentication Most endpoints require an API key. Pass it in one of two ways: Authorization Header (recommended) curl -H "Authorization: Bearer sk_yourkey" https://api.drop.cat/sites Form Field curl -F " [email&#160;protected] " -F "key=sk_yourkey" https://api.drop.cat/deploy How Keys Work When you deploy anonymously, the response includes a key field starting with sk_ . It is shown only once and cannot be recovered without a confirmed email on file. Keys are hashed server-side. We never store your plaintext key.
